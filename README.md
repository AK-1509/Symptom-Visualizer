# Drug Body Map

A visualization prototype that shows where FDA-labeled drug effects land on the human body. Add a drug, see which body regions its label talks about, then click a region (or drag the drug's pill onto it) to read the label text behind it.

> For informational purposes only. This visualization is not medical advice and does not diagnose, treat, or recommend medication use.

```sh
npm install
npm run dev        # http://127.0.0.1:5173
```

The app is a static site: React + TypeScript + Vite, an SVG body, and one JSON file of pre-processed label data. Nothing is fetched from FDA or anywhere else while you use it.

## Using it

1. Choose **AMAB / AFAB** and set the **age** slider (top).
2. **Search** by generic name, brand, alias or drug class (`sema`, `ozem`, `lip`, `paracetamol`, `ssri`); typos are tolerated. The same box also searches **label text**: mapped reaction terms and quoted sentences (`hepatotoxicity`, `tendon rupture`, `qt prolong`). Every word must appear in the same statement, as a word prefix. A label-text result adds the drug and opens the body region it was found in.
3. The drug joins **Active drugs** and its mapped regions light up:
   - **solid fill**: therapeutic use (Indications and Usage)
   - **hatching**: adverse reactions
   - **dashed outline**: warnings, boxed warnings and contraindications
   - a **number badge**: how many active drugs map to that region
4. **Click a region**, or **drag the pill** onto it, to open the details: matched terms, verbatim label sentences, and the section they came from, with a link to the label on DailyMed.

The whole flow works from the keyboard: Tab to the search box and the regions, Enter to select, Escape to close details.

### Age

The slider sorts age into three groups: pediatric (<18), adult (18–64) and geriatric (65+). It doesn't model pharmacology. When a label sentence names an age group ("in pediatric patients", "65 years of age and older"), that statement applies only to that group. It is emphasized when it matches and moves under "other age groups" when it doesn't. Statements that name no age group apply to everyone. For pediatric and geriatric ages, the details panel also shows the label's own *Pediatric Use* / *Geriatric Use* text.

### Sex

AMAB / AFAB changes the body drawing and filters label statements in the same way as age:

- **Tagging.** A sentence is tagged with one sex when it names that sex ("in women", "males"), or anatomy and states only one sex has (pregnancy, lactation, prostate, erectile function). A sentence that names both, or neither, applies to both.
- **Other sex.** Statements for the other sex are left off the body map and listed under "statements for another age group or sex".
- **Notes.** The details panel shows the label's own sex-specific sections for the selected body: *Pregnancy* (8.1) and *Lactation* (8.2) for AFAB, *Females and Males of Reproductive Potential* (8.3) split into its female and male parts, and any male/female difference stated in *Pharmacokinetics* (12.3), such as "C max and AUC were 20% higher in women", for both.

## Data

`public/data/drugs.json` holds **94 commonly used drugs** across cardiovascular, endocrine, psychiatric, neurologic, digestive, respiratory, infectious-disease, pain, immune and urologic use. The list is in [`scripts/drug-list.ts`](scripts/drug-list.ts). It is generated by `npm run data:build` from the [openFDA drug label API](https://open.fda.gov/apis/drug/label/), which serves the Structured Product Labeling published on DailyMed. This is a small demonstration set, not full FDA coverage.

### Pipeline

[`scripts/build-data.ts`](scripts/build-data.ts) runs these steps for each configured drug:

1. **Fetch.** Queries openFDA by generic name, by the configured brand, and for class-bearing labels. Raw responses are cached in `data/raw/` (git-ignored), so re-runs are offline. Pass `--refresh` to refetch, or `--only=id1,id2` to rebuild a few drugs.
2. **Pick one label.** Single-ingredient labels only, with the configured brand (usually the innovator, e.g. Lipitor) preferred, then completeness, then the newest date.
3. **Extract** Boxed Warning, Indications and Usage, Contraindications, Warnings and Precautions, and Adverse Reactions ([`src/lib/extract.ts`](src/lib/extract.ts)), plus Pediatric/Geriatric Use, Pregnancy, Lactation, Reproductive Potential and the male/female part of Pharmacokinetics as notes. Text is split into numbered subsections and sentences. The Highlights summary and cross-reference lists are recognized, and flattened tables are kept for term matching but never quoted.
4. **Map to anatomy** with a deterministic keyword/synonym table ([`src/lib/anatomy.ts`](src/lib/anatomy.ts)) onto 20 regions: brain, eyes, mouth & throat, heart, lungs, thyroid, stomach, intestines, liver, pancreas, kidneys, bladder, reproductive, blood, immune, skin, musculoskeletal, nervous system, endocrine, whole body. No LLM or NLP model is involved. A few rules keep the mapping honest:
   - A warning sentence belongs to its subsection's topic, so "dyspnea" listed as a thyroid-tumor symptom stays on the thyroid.
   - Indication wording such as "type 2 diabetes" is only treated as a therapeutic effect inside Indications.
   - Trial-population descriptions in Adverse Reactions ("at baseline…", "in patients with chronic kidney disease") are skipped.
5. **Write** compact JSON. Each sentence is stored once per drug, and effects point to it.

Full-text search runs entirely in the browser. An inverted index over terms and quoted sentences is built in idle time after the data loads (about 80 ms), and each query takes a few milliseconds.

### Provenance

Every effect carries `source`, `sourceUrl` (DailyMed set ID page), `section` (and subsection number and title when detectable) and `labelDate`. To keep the file compact, the label-level fields are stored once per drug and attached to every effect when the data loads ([`hydrate` in `src/lib/effects.ts`](src/lib/effects.ts)). Excerpts are verbatim label sentences, cut with an ellipsis past 280 characters. Cross-reference brackets like "[see Warnings and Precautions (5.1)]" are removed. Nothing is paraphrased, and no claim appears without its section and label.

The drug class comes from openFDA's established pharmacologic class when at least two labels agree. Otherwise it comes from the label's own wording ("… is a selective serotonin reuptake inhibitor indicated for …").

### Rebuilding or expanding the dataset

Add a row to `scripts/drug-list.ts`, then run `npm run data:build`. A full run takes about 5 minutes uncached, because of openFDA rate limits; set `OPENFDA_API_KEY` to raise them. Behind an HTTP(S) proxy, Node's built-in `fetch` needs `NODE_USE_ENV_PROXY=1` (Node ≥ 22.21).

## Known limitations

- **94 drugs, one label each.** Different products of the same ingredient (e.g. Ozempic vs. Wegovy) can have different labels; only the selected label is shown, and it is named in the details panel.
- **Keyword mapping is approximate.** It decides *where* a sentence points, not what it means. A region lights up because the label mentions it, which is not evidence of frequency or severity. Negations and comparisons ("was not reported", "similar to placebo") can still produce a mapping.
- **Age and sex handling is coarse.** Tags come from the wording of each sentence. Some labels are written entirely about one sex (the Viagra label studies men), so in the other view most of their statements move under "another age group or sex". Pregnancy and lactation notes show for AFAB at any age.
- **Full-text search covers the extracted statements only**, not the whole label: sections other than Indications, Warnings, Contraindications and Adverse Reactions, and sentences that map to no body region, aren't indexed.
- **No interaction data.** The overlap badge only says that several active drugs map to the same region; it does not infer interactions.
- Label text is reproduced as openFDA serves it, so occasional run-on sentences from flattened bullets and tables remain.
